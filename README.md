# Подбор запчастей

Клиентское приложение на React и JavaScript с Redux Toolkit / RTK Query, Bootstrap и SCSS. Данные поступают из Favorit Parts через серверный обработчик. Ключ поставщика остаётся на сервере.

## Сценарий работы

1. Введите артикул и нажмите «Найти» или Enter. При вводе запросов нет. Таблица сразу показывает детали разных производителей с этим артикулом, их склады, цены и остатки.
2. Для получения аналогов откройте «Фильтры», выберите производителя детали и нажмите «Применить». Запрос передаст артикул, бренд и `analogues=on`.
3. Выбор производителя находится только в панели фильтров. «Все производители» возвращает к первому ответу по артикулу без нового запроса.
4. В той же панели доступны локальные условия по складу, наличию и типу позиции. Кнопка показывает количество применённых условий; черновик действует только после «Применить». Когда условия применены, справа от «Найти» появляется «Сбросить фильтры»: производитель и локальные условия очищаются без нового запроса, артикул сохраняется.
5. Внизу слева кнопками выберите 10, 50 или 100 строк на странице. Все полученные предложения доступны, данные не обрезаются.
6. Значок в колонке цены переключает три состояния: исходный порядок, цена по возрастанию, цена по убыванию. Неизвестные цены остаются в конце.

Ввод нового артикула не меняет последнюю выдачу до отправки формы. Новый поиск сбрасывает прежнего производителя и фильтры. Результаты другого запроса не показываются во время загрузки нового поиска. Локальные фильтры не отправляют запросы поставщику. «Обновить» и «Повторить» явно запрашивают текущую выдачу; автоматического опроса и повторов нет.

Сортировка и пагинация также выполняются на клиенте, по полной загруженной выдаче. API поставщика не предоставляет параметры страниц в используемом контракте. Изменение фильтров, сортировки или размера страницы возвращает к первой странице.

## Валидация

Одна проверка используется в браузере и на сервере:

- артикул обязателен и должен содержать хотя бы одну букву или цифру;
- длина артикула ограничена 100 символами как правило приложения;
- управляющие и невидимые символы отклоняются;
- ведущие нули, внутренние пробелы, дефисы, `/`, `#`, `&` и другие печатные знаки сохраняются;
- производитель необязателен; для получения аналогов нужен выбранный бренд.

Артикул остаётся строкой, значение не преобразуется в число и не обрезается. Параметры кодируются через `URLSearchParams`. Неверный ввод не расходует запросы к поставщику.

## Запуск

Нужен Node.js 22.12+ или 24 и npm.

```bash
npm install
npm run dev
```

Скопируйте `.env.example` в `.env.local` и заполните `FAVORIT_API_KEY` и `FAVORIT_API_URL`. В шаблоне есть комментарии к настройкам; значения заполнены только для локальных адресов. Адрес внешнего API и ключ задаются в игнорируемом `.env.local` или в окружении серверного процесса.

Артикул и бренд выбираются в интерфейсе; задавать их в окружении не нужно. Серверные параметры читаются при каждом запросе. Префикс `VITE_` используется только для публичных настроек.

## API приложения

| Запрос | Действие |
| --- | --- |
| `GET /api/offers?number=01089` | Детали по артикулу без бренда и аналогов |
| `GET /api/offers?number=01089&brand=FEBI` | Запрос предложений выбранного производителя и аналогов |

Сервер добавляет ключ из закрытого конфига и возвращает `goods`. Клиент из одного ответа получает список производителей и строки таблицы: товары, вложенные `analogues` и склады. При выборе бренда остаются видны аналоги других производителей; дополнительного локального фильтра бренда нет.

Цена берётся только из `warehouses[].price`, остаток — из `warehouses[].stock`. Устаревшее общее `goods.price` не используется. Неизвестные числа показываются как «—». Реальный товар без складских предложений отображается без цены с нулевым наличием. Пустая структура «не найдено» не становится товаром.

Обработаны загрузка обоих этапов, отсутствие предложений, неверный ответ, ошибка доступа, квота, сеть и таймауты. При ошибке обновления прежние цены скрываются.

Контракт поставщика: [документация Favorit Parts](https://lk.favorit-parts.ru/static/wsprice.pdf). Валюта отображения настраивается в `src/config/app.js`, по умолчанию RUB.

## Проверки и запуск сборки

```bash
npm test
npm run build
npm start
```

`npm start` раздаёт `dist/` и обслуживает API без Vite. По умолчанию адрес — `http://127.0.0.1:3000`; `HOST` и `PORT` можно изменить в серверном окружении.

Тесты используют контролируемые ответы и не обращаются к поставщику.

## Структура настроек и логики

| Файл | Назначение |
| --- | --- |
| `vite.config.js` | Сборка, локальный сервер и подключение API |
| `.env.example` | Шаблон окружения без ключа |
| `src/config/app.js` | Публичные настройки интерфейса |
| `src/config/workplaces.js` | Существующее рабочее место |
| `server/config.js` | Закрытые настройки поставщика |
| `server/favoritMiddleware.js` | Запросы с необязательным брендом и обработка ошибок |
| `server/vitePlugin.js` | API в режиме разработки и предпросмотра |
| `server/index.js` | Сервер собранного приложения |
| `shared/searchValidation.js` | Общая валидация артикула и бренда |
| `src/api/partsApi.js` | Запросы, кеш и состояния загрузки в Redux |
| `src/api/normalizeBrands.js` | Список уникальных производителей |
| `src/api/normalizeOffers.js` | Преобразование товаров и складов |
| `src/store/searchSlice.js` | Поле ввода, выполненный поиск, выбранный бренд и фильтры |
| `src/pages/MainPage.jsx` | Выбор рабочего места по навигации |
| `src/components/layout/MainLayout.jsx` | Общая шапка, боковая панель и область рабочего места |
| `src/workplaces/parts/PartsWorkplace.jsx` | Композиция экрана подбора запчастей |
| `src/workplaces/parts/hooks/usePartsSearch.js` | Поиск, валидация и загрузка двух этапов |
| `src/workplaces/parts/hooks/useOfferView.js` | Фильтры, сортировка и текущая страница |
| `src/components/common/TablePagination.jsx` | Общий выбор размера страницы и навигация |
| `src/components/common/DataStatus.jsx` | Общие состояния загрузки и ошибок |
| `src/utils/offerView.js` | Чистые функции сортировки и пагинации |
| `src/styles/settings/_palette.scss` | Цвета по назначению |
| `src/styles/settings/_layout.scss` | Размеры, отступы и скругления |

Палитра названа по назначению: `$page-background` — фон страницы, `$panel-background` — рабочие блоки, `$text-main` — основной текст, `$text-muted` — подписи, `$action-primary` — основное действие, `$border-default` — границы. Компоненты используют эти роли через CSS-переменные.

Bootstrap подключён в `src/main.jsx`: формы, кнопки, таблица и индикаторы используют его классы. Общая SCSS-тема находится в `src/styles/`, а стили конкретных компонентов — рядом с их JSX. Вложенные BEM-блоки группируют элементы и состояния компонента.

Импорты между каталогами клиента используют `@/` → `src/`, например `@/components/common/DataStatus.jsx`. Общие модули клиента и сервера используют `#shared/` → `shared/`. Алиас `@` настроен в Vite, `#shared` — в `package.json`, а подсказки редактора — в `jsconfig.json`. Импорты соседних файлов остаются относительными.
